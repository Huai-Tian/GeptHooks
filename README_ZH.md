# GeptHooks

简体中文 | [English](README.md)

## 📖 介绍

**GeptHooks** 是一个通用的 Windows EPT 钩子框架（支持 Windows 10 - 11）。

它通过 Intel VT-x 虚拟化正在运行的系统，利用扩展页表（EPT）拦截内存的读取、写入与执行——让你的驱动可以钩取、监控或镜像替换任意内核/用户态地址的内容，而**不修改原始内存的任何一个字节**。

## ✨ 功能特性

- **执行钩子（隐藏断点）**
拦截内核或用户空间任意地址的执行。不使用 INT3、不篡改页表、不占用调试寄存器——对客户机完全不可见。

- **Inline EPT 钩子**
通过隐形跳板将执行流重定向到你的处理函数。从客户机视角看，原始代码完好无损。

- **读写监控**
像硬件调试寄存器一样监视内存读写——但没有 4 个槽位和长度限制。

- **内存镜像（Memory Shadowing）**
对同一页面分别呈现读取视图、写入视图和执行视图，三者内容可以各不相同。

- **VMFUNC EPTP 切换（零 VM-Exit）**
通过 VMFUNC 指令在干净视图与钩子视图间瞬时切换——指令级速度、无 VM-Exit，时序检测基本无效（需 Haswell 及以上 CPU）。

- **MSR 拦截（MSR Bitmap）**
伪造 IA32_LSTAR 等 MSR 的读取值，真实值仍处于你的控制之下——代码伪装与数据伪装同时达成。

- **Hypervisor 隐身（CPUID 伪装 + TSC 补偿）**
伪造 CPUID 结果清除 hypervisor 存在位，并以 TSC 补偿抹去 VM-exit 的时间开销——同时对抗基于 CPUID 与基于时序的 Hypervisor 检测。

- **简洁的驱动友好 API**
在你自己的内核驱动里用几个 C 函数调用即可完成钩子的安装、移除与枚举——无需任何 hypervisor 背景知识。

## ⚙️ 环境要求

- **CPU**：支持 VT-x 与 EPT 的 Intel 处理器（VMFUNC EPTP 切换需 Haswell 及以上）
- **操作系统**：Windows 10 / 11 x64
- **虚拟化冲突**：需关闭 Hyper-V、基于虚拟化的安全（VBS）、内存完整性（核心隔离）与 WHP——GeptHooks 必须作为根 hypervisor 运行
- **测试签名**：执行 `bcdedit /set testsigning on` 开启测试签名，或对驱动进行正式签名
- **构建**：Visual Studio 2022 + Windows Driver Kit（WDK）
- **运行**：管理员权限

## 🚀 快速开始

安装并启动驱动：

```
sc create GeptHooks type= kernel start= demand binPath= "C:\path\to\GeptHooks.sys"
sc start GeptHooks
```

停止并卸载：

```
sc stop GeptHooks
sc delete GeptHooks
```

在你的驱动中使用（预览版 API）：

```c
GEPT_HOOK Hook = { 0 };
Hook.TargetAddress = TargetFunction;
Hook.Type          = GeptHookExecute;
Hook.Callback      = OnTargetExecuted;

GeptHookInstall(&Hook);
// ... 你的测试逻辑 ...
GeptHookRemove(&Hook);
```
